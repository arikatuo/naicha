## Product Diagnosis

- Target User: 想轻量记录奶茶、偶尔回看自己饮用习惯的人。
- Core Value: 把本机的逐杯记录变成可理解的周、月、年概览。
- Core Action: 选饮品、看估算热量，喝过后存入日历。
- Aha Moment: 记过几杯后，看见杯数分布，并能回到具体日期。
- Retention Driver: 新记录会更新概览，旧记录可随时按日期回看。

## Top Problems

1. 原先只有日历逐日记录和当前月杯数，用户难以概览一段时间的记录。
2. 统计空白容易被误读为「没有喝」，而本地记录并不能证明这一点。
3. 汇总柱形若只跳到其中一天，会使多日总数与当日记录数不一致。

## Priority Changes

1. Problem: 缺少跨时间的回顾入口。Why users may leave: 记完后看不到逐渐积累的价值。Change: 已有记录的日历卡片增加统计入口，默认本月，可切换本周／本年。Expected behavior: 用户记录后回访概览。Metric: 有记录用户的统计入口点击率、第二次记录率。Impact / Confidence / Effort: 高／中／中；尚无实际使用数据，属于产品假设。
2. Problem: 数字口径可能误导。Why users may leave: 认为空白日期等于未饮用，或把估算热量当成精确值。Change: 全程写「已记录」，分别展示杯数与有记录天数，热量标「估算」。Expected behavior: 用户能正确理解概览。Metric: 统计页回访率、相关误解反馈。Impact / Confidence / Effort: 中／高／低。
3. Problem: 汇总与具体记录脱节。Why users may leave: 点击多杯柱形后只看到一杯。Change: 柱形展开该时段全部有记录日期和杯数，再由用户选日期。Expected behavior: 用户能顺利找到想回看的记录。Metric: 柱形展开后的日期点击率。Impact / Confidence / Effort: 中／高／中。

## UI / UX Changes

- 日历：有记录后，在已有的月度摘要中出现「查看本周／月／年统计」，不增加首屏空白导航。
- 统计：本月默认；杯数、有记录天数领先；分布图提供显式杯数，年度月份可横向滚动；热量合计降级并说明估算。
- 空状态：说明「这段时间还没有记录」仅指本机记录，并提供「选一杯，开始记录」。
- 回看：选柱形展开日期列表，选日期回日历；页面底部入口直达本期最近的有记录日期。

## Growth Opportunities

- Activation: 首次记录完成后，日历摘要成为统计入口；不提前要求登录或云存储。
- Retention: 统计随本地记录自然更新，提供有意义的回顾理由，不增加打卡压力。
- Sharing: 本期不展示个人统计分享入口；本地数据不应被默认制作成对外内容。
